# Move the Android build to AGP 9

## Intent

The build sits exactly on Flutter 3.47's `DependencyVersionChecker` error
floor (AGP 8.11.1 / Gradle 8.14 / KGP 2.2.20). The next Flutter release that
raises it breaks the build. Moving to the 3.47 template's versions now
clears the way for bumping Flutter later. Flutter itself stays at 3.47.7 in
this change.

**Success:** the release build passes on AGP 9.1.0 / Gradle 9.3.1 / KGP
2.4.0, Flutter's "support will soon be dropped" warning is gone, and the APKs
are unchanged: names `yomimoto_<version>-<abi>.apk`, version codes
`100 * build + {armeabi 1, arm64 2, x86_64 3}`, and signing via
`tool/build_release.sh`.

**Non-goals:** bumping Flutter, `targetSdk` or compileSdk; turning on
`android.newDsl` or `android.builtInKotlin`; converting the Gradle scripts to
Kotlin DSL.

**Anti-goals:** vendoring a plugin when the shim can handle it, and any change
to how the app behaves at runtime.

## Approaches

- **Match the template, keep both opt-out flags (chosen).** AGP 9.1.0, Gradle
  9.3.1 and KGP 2.4.0, with `android.newDsl=false` and
  `android.builtInKotlin=false`, as `flutter create` emits on 3.47.
- **Also enable `newDsl`.** Ruled out: Flutter's own Gradle plugin still needs
  the legacy variant API (its error message tells you to opt out).
- **Also enable `builtInKotlin`.** Ruled out: twelve plugins apply
  `kotlin-android` themselves, maintained ones included (`share_plus`,
  `device_info_plus`, `package_info_plus`, `wakelock_plus`, `audio_session`,
  `flutter_archive`, `receive_intent`), and AGP 9's built-in Kotlin rejects
  that. This waits on upstream packages.

## Design

1. Bump AGP and KGP in `android/settings.gradle`, and Gradle in
   `android/gradle/wrapper/gradle-wrapper.properties`.
2. Run a trial build and fix what breaks:
   - `kotlinOptions` → `kotlin { compilerOptions }` in the shim (applied
     under `plugins.withId("org.jetbrains.kotlin.android")`). The app has no
     Kotlin sources (`MainActivity.java` and `AnkiDroidHelper.java`), so drop
     its `kotlinOptions` block if KGP is no longer needed there. Whether the
     app still applies `kotlin-android` is the builder's call: the template
     doesn't apply it.
   - `com.android.build.OutputFile.ABI` in `applicationVariants.all`: replace
     it if AGP 9 removed it, keeping the same names and version codes.
   - The known risk is five plugins on `kotlinOptions`, which the shim can't
     fix if KGP 2.4.0 turns it into an error: `android_file_picker`,
     `external_path`, `flutter_exit_app`, `flutter_image_compress_common` and
     `flutter_logs`. Try a Gradle-configuration fix in the shim first. Fall
     back to `vendor/` only if that fails, or to a lower KGP still above
     Flutter's warning floor (2.3.20), noting the choice.
3. Verify: run `flutter build apk --release --split-per-abi` (and the signed
   `tool/build_release.sh`). Check the three APK names and their version codes
   (`aapt2 dump badging`), and that no version warning is printed. Then do a
   quick manual check on a device: launch the app, open a book, look up a
   word, and export a card to AnkiDroid.
4. Docs:
   - `docs/TOOLCHAIN.md`: update the version table, and replace "Why AGP 8,
     not AGP 9" with what the build actually showed.
   - Update the pin comment in `settings.gradle`.
   - `DEBT.md`: add an entry for the two opt-out flags (a future AGP removes
     them), naming the plugins that still apply KGP.

## Left to the builder

The exact replacement for `OutputFile`, the form of each plugin fix, and
whether `flutter analyze`/`flutter test` need re-running (they don't touch
Gradle, but CI runs them anyway).
